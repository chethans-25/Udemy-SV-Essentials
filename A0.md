### Initial Block

**Execution:** Starts at simulation time 0, executes once, and never repeats.

**Purpose:** Commonly used in testbenches to:

- Initialize signals
- Apply reset sequences
- Generate stimulus
- Display outputs or terminate simulation
- Call system tasks and functions

**Synthesizability:** Initial blocks are not synthesizable.

**Sequential execution:** Statements inside an initial block are executed sequentially, one after the other.

**Delay control:** Delay control can be used to specify the time at which a statement is executed.

### Always Block

**Execution:** Runs continuously throughout simulation, starting at time 0.

**Purpose:** Describes behavior that should repeat or react to changes in signals.

**Sensitivity:** Executes whenever signals in its sensitivity list change.

**Synthesizability:** Unlike `initial`, always blocks can be synthesizable, depending on how they are written.

#### Types

- `always_comb` - Combinational logic
- `always_ff` - Sequential logic (flip-flops)
- `always_latch` - Latches

A sensitivity list is not mandatory in a testbench.

```systemverilog
always #5 clk = ~clk;
```

If an always block is used without a sensitivity list, make sure to use a finish call.

### Timescale

Timescale defines the time unit and time precision. It determines how many decimal places can be used in simulation time.

```systemverilog
`timescale <time_unit>/<time_precision>
```

- `time_unit`: The base unit for delays, such as `1ns`, `10ps`, or `1us`.
- `time_precision`: The resolution or rounding of simulation time, such as `1ps` or `100fs`.

The default timescale is `1ns/1ps` if it is not specified.

The scope of the timescale directive is local to the file in which it is declared. It does not affect other files unless explicitly specified.

If the precision is not appropriate, `#5.6` may be rounded to `#6.0`, `#5.4` to `#5.0`, and `#5.5` to `#6.0`.

#### Dynamic Array

```systemverilog
int arr[];

initial begin
  arr = new[5];
  arr = '{1, 2, 3, 4, 5};

  arr = new[20];       // Erases previous data
  arr = new[20](arr);  // Retains previous data
end
```

#### Queue

```systemverilog
int arr[$];

initial arr = {1, 2, 3};  // Apostrophe is not needed

arr.push_front(7);        // 7, 1, 2, 3
arr.push_back(5);         // 7, 1, 2, 3, 5
arr.insert(2, 10);        // 7, 1, 10, 2, 3, 5

j = arr.pop_front();      // 1, 10, 2, 3, 5
// pop returns a value

j = arr.pop_back();       // 1, 10, 2, 3
arr.delete(1);            // 1, 2, 3
```

## Layered Testbench Architecture

1. **Signal layer:** DUT
2. **Command layer:** Converts signals to commands and commands to signals (Driver, Monitor, Interface)

## Section 5: Fundamentals of SV OOP Construct

## Classes

### Handles

- Memory allocation: object creation
- Create an object with `f = new();`
- Deallocate an object with `f = null;`
- Accessing a null pointer causes an error

### Class Methods

Class methods can be tasks or functions. Review the differences between them.

Use variables after defining methods. Otherwise, do not use arguments while defining tasks for variables that are already defined.

### Arguments

- Pass by value
- Pass by reference using the `ref` keyword

### Port Connection

Port connections can use names or positions.

Use an automatic task or function when passing by reference.

Use the `const` keyword if a value must remain unchanged when using `ref`.

### Constructors

- Use the standard constructor `new()`.
- Do not use `void` for this function.
- Use the `this` keyword where needed.

### Nested Classes

A subclass has access to modify members and methods.

Use the `local` keyword to restrict access, then use methods to get or set access.

Copy an object to another object when processing it without modifying the actual elements.

### Inheritance and Polymorphism

- **Inheritance:** Use the `extends` keyword.
- **Polymorphism:** Use the `virtual` keyword.
- Use the `super` keyword to access parent-class behavior.

## Randomization

- `rand`
- `randc`

Check whether randomization passed or failed using an `if` statement or an assertion.

Create a new object for new stimulus. Create the object inside the loop where randomization is called.

### Constraints

Use the `inside` keyword.

### External Constraints

Use the `extern` keyword. Add a semicolon at the end of the declaration when it is used externally.

### Randomization Hooks

- `pre_randomize`
- `post_randomize`

### Weighted Distribution

Use the `dist` keyword.

- `:=` assigns equal weights to all values inside a range.
- `:/` divides the weight equally among all values inside a range.

### Constraint Operators

- **Implication operator:** `->`
- **Equivalence operator:** `<->` (two-way implication)
- **If-else operator:** Use curly braces where required.

### Constraint Mode

Disable a constraint:

```systemverilog
constraint_mode(0);
```

Enable a constraint:

```systemverilog
constraint_mode(1);
```

`constraint_mode()` returns the constraint mode status (`0` or `1`).

### Event

Example declaration:

```systemverilog
event a;
```

**Trigger:**


```systemverilog
@(a);
```

```systemverilog
wait(a.triggered);
```

Use events with `trigger` and `wait` in generator and driver code.

### Fork-Join

- `fork ... join`
- `fork ... join_any`
- `fork ... join_none`

| Construct | Behavior | When Does Control Return? | Typical Use Case |
| --- | --- | --- | --- |
| ``fork-join`` | Starts multiple parallel threads | Waits until *all* threads finish | Synchronize after all parallel tasks complete |
| ``fork-join_any`` | Starts multiple parallel threads | Returns as soon as *any one* thread finishes | Trigger action when the first task completes |
| ``fork-join_none`` | Starts multiple parallel threads | Returns immediately, without waiting | Fire-and-forget background tasks |

### Semaphore


### Mailbox

```systemverilog

```

#### Mailbox Methods


#### Common Mailbox Usage

**Method 1:**


**Method 2:** Use the following assignment in the standard constructor:

```systemverilog

```

Mailboxes can be parameterized.
